# Tada! MVP 产品方案 v0.1

## 1. 问题与价值

目标用户是存在任务启动、日常执行或分心后恢复困难的成年人，包括有 ADHD 相关体验的人；无需提供诊断证明。首批研究暂聚焦学生与求职者，这是招募与展示范围的建议，尚无访谈数据。

核心任务：当一件事太模糊、太大，或中途断开时，帮助我确定下一步实际动作，并在返回时接上。

价值假设：比起再增加一个待办清单，用户更需要把“整理作品集”变成“打开文档，写下一个项目名”，并由自己决定是否开始。AI 的作用是结合情境生成和缩小动作，界面负责保存进度与减少选择负担。

## 2. MVP 边界

| 优先级 | 功能 | 目的与验收 |
| --- | --- | --- |
| P0 | 一句话输入 | 空输入明确提示；不先做复杂入门问卷；用户可补充可用时间与精力，但非必填 |
| P0 | AI 微行动 | 初次最多三步，只突出第一步；第一步为具体可观察动作；支持编辑与“再小一点” |
| P0 | 行动状态 | 点击“就做这一步”才记录开始；完成、暂停和分心均保留上下文 |
| P0 | 分心恢复 | 用户主动点击“我分心了”；呈现原任务与当前动作，可继续或进一步缩小 |
| P0 | 小步完成 | 用户确认完成才计完成；卡片内庆祝；可继续下一步或暂停 |
| P0 | 进度保存 | 刷新后恢复到最近任务的准确状态；保存失败有可见提示，不显示虚假的“已保存” |
| P0 | 异常与可访问性 | 生成失败可重试或手填；键盘可用；减少动效；不会丢弃输入 |
| P1 | 今日视图 | 默认最多三项；完整历史可展开，无惩罚性逾期标记 |
| P1 | 可选陪伴与计时 | 静态/微动效、可关闭计时；验证需求后再做 |
| 暂缓 | 复杂日历、后台推送、社交排名、养成商城、语音常驻、多代理自动执行 | 保持求职 Demo 范围可控 |

首版不做账号、跨设备同步或自动监测分心。MVP 并不等于完整的每日计划管理器。日常执行先通过同一套微行动流程支持。

## 3. 主流程与状态

首页输入 → 生成中 → 确认微行动 → 行动中 → 完成小步 → 继续下一步 / 暂停。

行动中 → 我分心了 → 恢复卡 → 继续当前步 / 再小一点 / 暂停。

状态建议：draft、generating、ready、active、recovering、paused、step_done、task_done、generation_failed。只有所有必要步骤完成且用户确认，才进入 task_done；完成一小步不能被自动解释为完成整个项目。

生成时允许回到草稿；返回后出现的迟到响应不能覆盖更新的输入。重试不新增重复任务。刷新恢复不触发再次生成，不把 active 自动改为 completed。已经开始后缩小动作，保留旧动作和修订版本，不丢失完成记录。

## 4. 三个关键页面

**开始页**：标题“今天想先动哪一小步？”；输入“想做的事”；主按钮“帮我找第一步”；可选入口“我已经知道第一步”。首页不要求用户先给任务分项目、优先级、截止日期。

**行动页**：显示任务名与当前步骤。示例：“打开作品集文档，写下一个项目名。”主操作在开始前为“就做这一步”，开始后为“完成这一步”；次操作“再小一点”“我分心了”“暂停”。后续步骤折叠。

**恢复/完成状态**：恢复时显示“刚才：作品集 → 当前：写下项目名”；主按钮“接着做这一步”。完成时显示“这一小步完成啦”，让用户选择继续或休息。

## 5. 主演示案例

输入：我得做 AI 产品经理作品集，但完全不知道怎么开始。

首次建议：① 打开一个空白文档，写上 Tada!；② 写一句它想帮助谁；③ 记录一个用户卡住的场景。当前只突出①。

点击“再小一点”：把①改为“先打开一个空白文档”。用户开始后离开，返回点击“我分心了”，界面提示“刚才在开始作品集。下一步：打开空白文档。”完成后显示庆祝，可接着写项目名。

此案例是设计样例，不是已运行的模型结果，也不是实测效果。

## 6. 数据与权限草案

建议记录 Task(id, 原始输入, 创建时间)、Step(id, task_id, revision, 动作, 状态)、Session(当前任务/步骤)、Event(事件类型, 时间, task_id, step_id)。修订采用新增版本，状态更新采用追加事件；完成次数按 step_id 去重。

初期建议使用浏览器本地 IndexedDB 保存，追加事件并在重开时恢复状态。外部持久存储与部署留待后续实施决定。产品不实现删除、清空或自动清理；这会带来存储增长和共享设备隐私限制，首轮 Demo 只用合成示例，不收集健康史。

如果后续接入真实模型，生成前明确说明：当前任务文本及用户主动选择的补充信息将发送给模型服务；提供手动模式。密钥只放服务端。未经用户选择，不上传完整历史；事件日志不含任务正文。数据保留及供应商条件需在选型时核实。

## 7. 验收清单

- 输入模糊任务后得到最多三步；用户能修改并仅开始当前步。
- “太大了”至少可再缩小一次，旧动作可追溯。
- 分心或暂停后，刷新仍能找到原任务、当前步骤和已完成记录。
- 失败、断网、重复点击和迟到响应不会丢弃输入或造成重复完成。
- 手动模式不依赖模型；提供可走完整流程的方式。
- 动效可关闭、操作有文字标签、主流程可用键盘完成。
- 不出现羞辱文案、排名、连续打卡惩罚和未经同意的提醒。
- 真实 AI、样例数据、人工预设输出在演示中明确区分。
