# Tada! 验证与求职展示计划 v0.1

## 1. 先验证什么

H1：用户能在少量阅读后理解并愿意尝试第一步。H2：恢复卡能帮助用户重新找到当前动作。H3：软萌风格带来陪伴感，同时不会增加干扰或让用户感觉被幼化。H4：用户认为情境化微行动比自己写一个待办更有帮助。

这些均为假设，没有已有访谈、上线数据或临床效果证据。可用性和主观体验不能证明 ADHD 症状改善。

## 2. 首轮研究

建议招募 5 位有相关执行困难体验的成年学生或求职者；自愿参与，不要求披露诊断。5 人用于发现早期问题，不能推断总体效果。演示与录屏分别征得同意；遵守永久不删除约束，首轮不收集健康史、不录制个人敏感任务，默认使用合成任务，仅保留匿名问题笔记。

访谈先问真实经历：最近一次想做却迟迟没开始的事是什么？当时卡在哪？中断后如何找回？用过什么方法，哪一步最麻烦？避免先问“你喜不喜欢我们的可爱 AI”。

可用性任务：输入一个合成的作品集任务；把第一步缩小；开始后切去另一页面，再回来看如何接上；完成一步并暂停。观察是否需要主持人提示。测试温柔角色版与更简洁版，交替呈现顺序；收集喜欢程度与实际操作表现，不把风格偏好当疗效。

## 3. 指标与埋点

| 指标 | 操作定义 | 解释限制 |
| --- | --- | --- |
| 启动率 | 显示有效第一步后10分钟内点击开始的唯一会话 / 显示有效第一步的唯一会话 | 点击不等于线下实际行动；由访谈补充 |
| 启动用时 | 第一张有效步骤卡显示至首次点击开始的时长 | 同时报未启动比例，不能仅看成功者 |
| 恢复率 | 打开恢复卡后10分钟内点击继续的会话 / 打开恢复卡的会话 | 仅衡量使用了恢复入口的人 |
| 小步完成率 | 开始后24小时内用户确认首步完成的会话 / 开始的会话 | 自报完成，不是临床效果 |
| 负担与语气 | 任务后询问“操作费力吗”“有被催促吗”，1–5分及原因 | 小样本只报告计数、原话和范围 |

初始事件：task_submitted、step_shown、step_shrunk、step_started、recovery_opened、step_resumed、step_completed、session_paused、generation_failed。含匿名会话 id、任务/步骤 id、时间、schema 版本，不含正文。分母、观察窗口、去重方式和缺失样本均随报告保留。首轮研究不设置虚假的增长目标；先取得基线，再确定改进门槛。

内部可用性门槛建议：5 人中至少4人不需主持提示走完核心流程，且无人遇到阻断性的恢复失败；这是设计门槛提案，不是已取得结果。

## 4. 三分钟演示脚本

0:00–0:25：说明具体问题——“知道要做作品集，却卡在第一步；回来后也容易忘记刚才做到哪里。”不要用未经调研的市场规模或效果数字。

0:25–1:15：输入“想做 AI 产品经理作品集”；生成微行动；点“再小一点”；选择开始。说明 AI 负责把模糊目标转成情境化动作，用户保留决定权。

1:15–2:00：模拟分心，回到恢复卡；显示原任务与当前一步；确认完成，出现安静庆祝。

2:00–2:30：演示生成失败后的手动模式，以及刷新后保留进度。明确当前是真实模型、手动模式还是预设示例。

2:30–3:00：展示验证表：观察了什么、发现什么失败、如何调整。未开展研究前展示研究计划，不填编造数据。

## 5. 分阶段实施顺序

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 当前：规划 | 品牌方向板、MVP、AI 约定、研究与演示计划 | 形成可审阅的方向，本次已完成 |
| 下一步：交互原型 | 首页、微行动、恢复与完成状态 | 用合成任务可走通，无需真实模型 |
| 再下一步：可运行 Demo | 本地状态、手动模式、AI 服务接口 | 主流程、异常和刷新恢复验收通过 |
| 之后：研究与作品集 | 真实观察、改版对照、评测记录、3分钟演示 | 所有指标标记样本与限制 |

实施尚未开始。等待用户指示后再确定技术栈、模型供应商和部署方式；在此之前不创建账号、消耗模型费用或发布网站。

## 6. 求职材料结构

问题情境 → 用户证据与假设 → 方案取舍 → 核心交互 → AI 输入输出与质量控制 → 可用性发现 → 迭代 → 限制与下一步。每一页都区分“已观察”“已实现”“待验证”。保留失败案例和缩减范围的理由，体现 AI 产品经理判断。
